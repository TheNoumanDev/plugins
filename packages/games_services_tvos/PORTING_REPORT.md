# games_services_tvos — porting report

Generated by `flutter-tvos plugin port` on 2026-09-02, then corrected by
hand. The generated report claimed a clean port with nothing disabled and
nothing to review; that was wrong on both counts, and the sections below
are what a build and a run actually produced.

Source: `games_services` 5.3.0 (shared `darwin/` implementation)
Base platform: ios (Swift)
Output: `packages/games_services_tvos`

## What the generated report got wrong

The porter's own inventory listed four "methods" — `bottomLeading`,
`bottomTrailing`, `topLeading`, `topTrailing`. Those are `GKAccessPoint`
**locations**, not method-channel handlers; the real handler set
(`signIn`, `submitScore`, `loadLeaderboardScores`, …) was never
enumerated. It then reported "✅ No tvOS-incompatible APIs detected" and
"0 disabled".

The compiler disagreed, with four errors. This is the documented limit of
regex-based porting rather than a defect — but it does mean the report is
a starting point, not a verdict.

## Disabled on tvOS

`tvos/Classes/SaveGame.swift` — all four entry points, guarded
`#if os(tvOS)`:

| Method | Missing API |
|---|---|
| `saveGame` | `GKLocalPlayer.saveGameData(_:withName:completionHandler:)` |
| `getSavedGames` | `GKLocalPlayer.fetchSavedGames(completionHandler:)` |
| `loadGame` | `GKLocalPlayer.fetchSavedGames(completionHandler:)` |
| `deleteGame` | `GKLocalPlayer.deleteSavedGames(withName:completionHandler:)` |

All four are declared `API_UNAVAILABLE(tvos, watchos)` in
`GKSavedGame.h`. There is no substitute and no partial version: Game
Center does not store save data for tvOS apps.

Note that `GKSavedGame.h` **is** present in the tvOS SDK, and
`GKSavedGame` itself is a usable type — so checking that the header
exists is not enough to conclude the feature does. The availability
attributes are on `GKLocalPlayer`'s category methods.

Each guarded method returns the new `saved_games_unavailable` error
rather than going unanswered, so Dart sees an absent feature instead of
a `MissingPluginException` that reads like a broken install.

## Ported unchanged

Everything else is the iOS code path, not a reduced one. The three things
that forced compromises in the watchOS sibling are all present on tvOS:

- `GKLocalPlayer.local` (tvOS 13+) — watchOS has only `localPlayer`
- the two-argument `authenticateHandler` `(UIViewController?, Error?)` —
  watchOS has the degraded one-argument form
- `gamePlayerID` / `teamPlayerID` (tvOS 12.4+), both
  `API_UNAVAILABLE(watchos)` — their absence is what forced
  `games_services_watchos` to identify the local player by rank

`GKGameCenterViewController` and `GKAccessPoint` are also present, so
`showLeaderboards` / `showAchievements` open Apple's own native UI.

## Hand-finished

1. **Removed the vendored Dart.** The porter copied the whole upstream
   public API into `lib/src/` — `Leaderboards`, `Achievements`, `Player`,
   `SaveGame` and their models. This package is native-only: the
   platform interface's default `MethodChannelGamesServices` already
   drives the `games_services` channel, and an app imports the upstream
   package, not this one. The copy was unreachable and would have gone
   stale, so `lib/` is now a documentation-only library, matching
   `wakelock_plus_tvos`.

2. **Widened the interface constraint** from `^5.3.0` to
   `>=4.1.1 <6.0.0`. The Swift came from 5.3.0 but answers 4.x too:
   identical channel name, 5.3.0's `Method` enum is a strict superset,
   and every argument key 4.1.1 sends is read unchanged — the sole
   addition, `ignoreImages`, defaults to `false`, which is 4.x's
   behaviour. Without this an app could not use the wrist and the TV
   together, since `games_services_watchos` pins `^4.1.1`.

3. **Lowered the deployment target** from the generated `tvos 15.0` to
   `14.0`, matching upstream's own iOS floor. Everything newer in the
   sources is `#available`-guarded at runtime, so 15.0 excluded devices
   for nothing.

4. **Package metadata** moved to the repo convention
   (`homepage: https://fluttertv.dev`, `repository:` pointing into
   `fluttertv/plugins`), and the SDK constraint set to the house floor —
   this package's own Dart requires nothing, and whichever
   `games_services` the app picks brings its own.

## Verification, and a toolchain caveat

**The bundled `example/` cannot verify this port**, and neither can any
other example in this repository. Plugin discovery
(`_walkPluginDependencies` in `flutter-tvos/lib/tvos_plugins.dart`) reads
the `dependencyGraph` out of `.flutter-plugins-dependencies` — and that
file is written by Flutter's own `refreshPluginsList`, which produces
nothing for a project with no platform directory it recognises. A
tvOS-only example has only `tvos/`, so the file is never written, the
graph is empty, and **zero plugins are discovered**. Confirmed with both
`flutter-tvos pub get` and stock `flutter pub get`.

This is worth stating plainly because of how it fails: the example still
**builds green**. It builds green precisely because the plugin was never
registered, so its Swift was never compiled — and the four saved-game
errors above went unseen until the package was added to a real app that
has an `ios/` directory alongside its `tvos/` one.

Verified instead in a host app (an existing tvOS game):

- `@import games_services_tvos;` and
  `[SwiftGamesServicesPlugin registerWithRegistrar:…]` appear in the
  generated `GeneratedPluginRegistrant.m`
- the app builds and links green for `appletvsimulator`
- resolution picks `games_services 4.1.1`, exercising the widened
  constraint
- **the channel answers in both directions.** `GameAuth.signIn()` from
  Dart reached the native side, which set
  `GKLocalPlayer.local.authenticateHandler`; GameKit called back with a
  view controller and the plugin presented it — Apple's own "Welcome to
  Game Center" screen appeared on the Apple TV. Dismissing it with
  *Not Now* completed the round trip, and Dart received
  `PlatformException(failed_to_authenticate, "… local player has not
  been authenticated")` — a structured error from the plugin, which is
  the correct answer to declining, and categorically not the
  `MissingPluginException` an unregistered plugin would have produced.
- **every handler in the dispatch was called and answered.** Driving all
  seven from Dart on the simulator, with sign-in declined:

  | call | result |
  |---|---|
  | `saveGame`, `loadGame`, `getSavedGames`, `deleteGame` | `saved_games_unavailable` |
  | `submitScore` | `failed_to_send_score` + *"local player has not been authenticated"* |
  | `loadLeaderboardScores` | `failed_to_load_leaderboard_scores` + the same |
  | `isSignedIn` | `false` |

  The first row is this port's own code, executed rather than merely
  compiled — all four `#if os(tvOS)` branches fire and return a
  structured error instead of hanging. The next two carry **GameKit's**
  message, not ours, so those handlers genuinely reach GameKit and come
  back; and they return *different* error codes, so the dispatch routes
  to distinct handlers rather than one fallback.

  What this still does not show is a *successful* authenticated call.
  The errors are GameKit refusing an unauthenticated player, which is
  correct behaviour for a declined sign-in, not evidence a submit or a
  read would succeed.

- [x] Every disabled region documented above and in `README.md`
- [x] Removed imports confirmed not load-bearing (all macOS imports were
      already `#if`-guarded by the porter, correctly)
- [x] Builds green in a host app **with the plugin actually registered**
- [x] `CHANGELOG.md` written for 0.0.1
- [x] Authenticated round trip on a physical Apple TV (tvOS 26.6) signed
      into a real Game Center account: `isSignedIn` true, the alias and
      `gamePlayerID` both resolve, `submitScore` returns `Success`,
      `loadLeaderboardScores` returns entries, and `getPlayerScore` reads
      back the player's existing best rather than the probe's own write.
      The saved-game guards return `saved_games_unavailable` on hardware
      as they do on the simulator.

      This is the check the watchOS sibling failed: it authenticated
      cleanly and still could not read, because its local player had no
      resolved alias. tvOS has `gamePlayerID` / `teamPlayerID` — both
      `API_UNAVAILABLE(watchos)` — and does not reproduce it.

      Scores went to Game Center's **sandbox**, which is what a
      development-signed build uses.
- [ ] Integration tests under `example/integration_test/`. Deliberately
      not written yet: per the caveat above the example cannot register
      the plugin, so every test would fail with `MissingPluginException`
      for reasons having nothing to do with the code under test. Tests
      that cannot execute are worse than none — the wiring contract is
      covered by `test/` instead, which does run.
